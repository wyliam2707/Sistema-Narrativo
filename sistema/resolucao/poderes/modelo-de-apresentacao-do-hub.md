# Modelo de apresentação do Hub

Status: APROVADO

Este arquivo define o **modelo universal de apresentação ao JOGADOR HUMANO** para todos os Hubs de Poder.

Os arquivos individuais dos Poderes continuam guardando regras, custos, exemplos, exceções e explicações completas. Este modelo define somente **como o Hub aparece na mesa**.

> **Arquivo detalha. Hub apresentado resume.**

## Regra universal

Quando um Hub for mostrado ao JOGADOR HUMANO:

- não inserir linhas em branco dentro do Hub;
- usar uma linha para o nome do Poder e `[X]`;
- usar uma linha por campo relevante;
- manter os campos na ordem definida pelo próprio Poder;
- mostrar somente opções consultáveis ou configuráveis naquele uso;
- não mostrar cálculos internos, justificativas, exemplos ou texto explicativo que não sejam necessários para uma escolha real;
- não repetir regras que o jogador não precisa decidir naquele momento;
- manter setas `→` para progressões;
- manter colchetes e valores exatamente quando fizerem parte da opção;
- não transformar a apresentação em relatório mecânico.

## Forma básica

```text
Nome do Poder [X]
Campo 1: opção → opção → opção
Campo 2: opção → opção
Campo 3: opção → opção → opção
Campo fixo: valor
```

Só aparecem os campos que realmente pertencem ao Poder.

Não criar linhas vazias entre eles.

## Exemplo canônico

```text
Golpe [X]
Alcance: Toque → Próximo (~3 m)
Alvos: 1 → 2 → 4
Área: Alvo → Próximo (~3 m)
Dano: 1d8 → 2d8 → 3d8 → 4d8 [+Potência]
Efeito: Nenhum
Defesa: Total → Parcial
Efeito [Nula]
```

O exemplo define a **forma**, não os campos obrigatórios. Um Poder que não possui Área, Dano, Defesa ou qualquer outra linha simplesmente não mostra essa linha.

## Configuração durante o uso

Quando o jogador declarar um Poder:

```text
consultar arquivo completo internamente
→ montar somente o Hub visível
→ apresentar em bloco compacto
→ receber apenas escolhas ainda necessárias
→ resolver
```

Se parte da configuração já estiver determinada pela declaração do jogador, não pedir novamente.

Se uma opção permanecer na posição inicial por regra, não criar confirmação adicional apenas para confirmar que ela continua na posição inicial.

## Exceções

Uma regra específica de Poder pode exigir uma informação adicional no Hub quando essa informação for realmente necessária para a escolha do jogador.

Mesmo nesse caso, preservar o formato compacto e sem linhas vazias.

## Regra final

> **Todos os Hubs de Poder apresentados ao JOGADOR HUMANO usam este modelo: bloco compacto, uma linha por campo relevante, sem espaços vazios e sem mecânica interna desnecessária.**
